# About me

- I'm a biologist (B-cell development and leukaemia), not a programmer.
- I can read R output and plots, but I don't write code from scratch.

# How to work with me

- Explain each step in plain English before you run it, and say what it will change.
- Plan first. For anything bigger than a one-line change, show me the plan and wait for "go".
- One step at a time. "The next step" means only the next step, not the rest of the analysis.
- Ask, don't guess. If a sample name, threshold or file is ambiguous, ask me.
- Never commit, push, delete or overwrite files without asking me first.

# Facts and sources

- Say whether an answer comes from your training data, a web search, or a file you read.
- Cite sources as PubMed or DOI links. Never invent a citation: if you can't find one, say so.
- Flag uncertainty and conflicting studies. Don't smooth them over.

# Data

- Never send data to a website or service I haven't approved.
- Treat any folder called `raw/` as read-only.
